## Главное правило

**Никогда не жди другого агента.** Занятость определяется только живым
claim'ом на конкретный файл. Если файл не занят — он свободен, бери его.
Агент, который исчез, не должен блокировать работу: его claim протухает и
освобождает файлы автоматически.

## Обязательное чтение перед любой работой

1. `.agent-handoff.json` — живое состояние: claims, hints, task_log
2. `.agent-protocol.json` — **канонические правила**: зоны, гейты, контракты,
   границы, приоритеты
3. `docs/agent-status.json` — оперативный снимок: кто что делает, последние гейты
4. `docs/PROJECT_STATUS.md` — состояние продукта и дорожная карта

Затем:

```
python scripts\agent_handoff.py status
python scripts\agent_handoff.py who-owns <файл>
python scripts\agent_handoff.py backlog list
```

**Раздел `contracts_easy_to_break` в протоколе читай обязательно.** Это
единственное место, где написано, что ломать нельзя.

## Твоя личность — выбирай сам

Имя агента выбирается тобой при первом обращении к репозиторию. Оно может быть
любым: `claude-opus`, `gpt-5`, `codex`, `sub-7`, что угодно.

- Имя — **только идентификатор** для разрешения конфликтов и отчётности.
- Имя **не даёт** тебе никакой зоны и никаких прав.
- Владение файлом = последний живой claim на него. Не по имени, не по зоне.

### Если ты субагент

- Возьми **отдельный** claim с именем `<имя-основного>/<роль>`, например
  `codex/sub-auditor`. Иначе два параллельных исполнителя будут считаться
  одним и столкнутся молча.
- Субагент снимает **только свой** claim и пишет в task_log **только под своим**
  именем.

### Если твоё имя уже держит живой claim

Это почти всегда перезапущенная сессия, а не второй агент. Возьми имя вида
`<твоё-имя>/2`. Молча переиспользовать имя опаснее: файлы первой сессии станут
свободными, а первая сессия продолжит их править.

## Зоны — подсказка, а не запрет

Зоны описывают **области кода**, а не людей. Любой агент может работать в любой
зоне. Зона нужна только чтобы понимать, где ты, а где коллега.

Актуальный список зон — в `.agent-protocol.json` → `zones`. Не memorize его:
он меняется вместе с проектом.

Если твой файл не попал ни в одну зону — **это не повод ждать**. Claim его и
работай; зону можно дополнить позже.

## Цикл работы

1. Прочитать координационные файлы и `contracts_easy_to_break`.
2. **Снять baseline**: `python -m pytest -q` (или `scripts\dev.py gates`) ДО
   правок, чтобы знать, что было зелёным без тебя.
3. Проверить занятость: `status` и `who-owns <файл>`.
4. Занять область: `claim <ты> "<задача>" --files <файлы>`.
5. Править атомарно; чужой файл перечитывать **непосредственно перед** записью.
6. Heartbeat, если задача дольше 30 минут.
7. Прогнать гейты.
8. `log-entry` с реальными командами и числами.
9. Обновить свой раздел журнала через `status-set`.
10. `release` и удалить scratch.

### Команды

```
python scripts\agent_handoff.py status
python scripts\agent_handoff.py who-owns <файл>
python scripts\agent_handoff.py backlog list
python scripts\agent_handoff.py claim "my-agent" "задача" --files "a.py,b.py"
python scripts\agent_handoff.py heartbeat "my-agent" --note "прогресс"
python scripts\agent_handoff.py release "my-agent"
python scripts\agent_handoff.py log-entry --agent "my-agent" --file entry.json
python scripts\agent_handoff.py hint "To <адресат>: ..."
python scripts\agent_handoff.py status-set agents.my-agent.status DONE --agent my-agent
python scripts\agent_handoff.py health-check
python scripts\agent_handoff.py validate
python scripts\dev.py gates
```

## Claims

- Один claim — одна проверяемая задача. Не смешивай фикс и рефакторинг.
- Heartbeat обязателен после 30 минут.
- **Claim протухает через 90 минут без heartbeat.** Устаревший claim не держит
  файлы: можешь взять их с `--force` и написать об этом в `coordination_note`.
- Всегда снимай claim. Если тебя прервали — восстановление через протухание.
- Пиши координационные файлы **только** через `scripts/agent_handoff.py`.
  Ручные правки проигрывают гонку.

## Гейты

Минимум перед завершением:

```
python -m pytest -q
python scripts\agent_handoff.py validate
```

Полный набор (если настроен `scripts/gates.json`):

```
python scripts\dev.py gates
```

Красный гейт — работа не сдана. Пропущенный гейт — это **не** успех: он
означает, что проверка фактически не выполнялась.

`validate` возвращает код 1 только для **блокирующих** проблем (битый
координационный JSON, mojibake). Старые записи task_log без полей — это
предупреждение, а не твоя регрессия.

---

## Формат записи в task_log

```json
{
  "date": "YYYY-MM-DD",
  "task": "краткое имя задачи",
  "author": "твоё-имя",
  "status": "DONE | IN_PROGRESS | BLOCKED | ABANDONED",
  "description": "что изменилось и почему; причина важнее результата",
  "changed_files": ["..."],
  "verification": "точные команды",
  "result": "измеренные числа, а не 'работает'",
  "next_agent_hint": "обязательно, если status != DONE",
  "coordination_note": "владение, конфликты, договорённости"
}
```

Поля сверяются с `handoff_entry_schema` в протоколе.

## Приоритеты

| | |
|---|---|
| **P0** | падает гейт; ImportError, AttributeError, SyntaxError; сломан основной путь от входа до результата; повреждены coordination-JSON; публичный контракт не читается |
| **P1** | брошенная задача; протухший claim; ломаешь другого агента; сломана кросс-компонентная интеграция |
| **P2** | работа в своей зоне |
| **P3** | новые фичи |
| **P4** | рефакторинг без измеренного дефекта |

При открытом P0 не начинать P3/P4. Проверь: `backlog list`.

## Контракты, которые легко сломать

Читай `.agent-protocol.json` → `contracts_easy_to_break`. В шаблоне этот раздел
пуст — **заполни его первым делом**, иначе каждый агент будет заново ломать
одни и те же вещи.

Типовые формы, которые стоит внести сразу:

- **Схема данных** — изменение набора полей требует новой версии схемы.
- **`-1` (или иной sentinel) означает «не проверено»**, а не «чисто»:
  ранжирование и фильтрация обязаны трактовать это как «неизвестно».
- **Бюджеты** действуют на весь прогон, а не на батч.
- **Формат файла на границе**: что пишет один компонент и что читает другой
  по именам.
- **Словарь статистики**, на который ссылаются тесты и бенчмарки.

## Границы

Проектные границы — в `.agent-protocol.json` → `boundaries`. Типовые:

- Тесты: `port=0`. Ручные серверы — отдельный диапазон (например,
  18900–18999), и разные сервисы на разных портах.
- Кэши и базы: тесты используют `tmp_path`, бенчмарк — отдельный файл.
  Runtime-базу как тестовый кэш не использовать.
- Существующие артефакты (чекпоинты, снапшоты) не перезаписывать; новые — с
  датой и версией.
- `reserved`-зона: сначала запиши своё имя в `zones.reserved` протокола,
  потом бери с `--force` и предупреди команду через `hint`.
- Не коммитить: `.venv/`, `build/`, `*.egg-info/`, `*.db`, `.scratch/*`,
  `.agent-events.jsonl`, `.agent-handoff.backups/`.

**ЛОВУШКА**: в некоторых окружениях `tempfile.gettempdir()` возвращает **корень
репозитория**, а не системный temp. Любой `mkdtemp()` без `dir=` окажется в
рабочей копии. Проверь это у себя (`python -c "import tempfile; print(tempfile.gettempdir())"`)
и создавай папки явно (`.scratch/<агент>/<задача>/`), удаляя в `finally`, в том
числе при провале.

## Если что-то не так

- `who-owns` говорит `СВОБОДНО` — файл твой, можно брать.
- Занято живым claim'ом — выбери другую задачу или подожди `release`.
- Claim протух — бери с `--force`, объясни в `coordination_note`.
- Файл изменился между чтением и записью — перечитай, не применяй старый патч.
- Найденный чужой баг — это подсказка владельцу зоны через `hint`, а не повод
  молча переписать чужой код.

## Dashboard (наблюдение, не инструмент)

```
python scripts/agent_dashboard.py
http://127.0.0.1:18900
```

Требует `fastapi` и `uvicorn`. Показывает агентов, claims, занятые файлы,
P0/P1, hints, task_log и последние гейты. **НИКОГДА не пишет в
coordination-файлы.** Если не установлен или не запущен — работа продолжается
нормально.

## Правила работы

- Проверяй гипотезу замером, прежде чем чинить.
- Сообщай о неудаче честно, включая неудачные попытки. «Работает» без команды
  и результата бесполезно.
- Не подделывай поля в записях: незнание фиксируется честно (`legacy_entry`),
  а не выдуманным значением.
- Не усложняй координацию без нужды. Цель — держать гейты зелёными.
