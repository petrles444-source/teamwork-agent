# docs/rfc — предложения по изменению

Один файл = одно предложение. Имя: `ГГГГ-ММ-ДД-короткое-имя.md`.

Протокол: `docs/rfc/0000-template.md`.

Нумерация по дате, а не по счётчику: при параллельной работе два агента
одновременно возьмут «0001», и один из файлов перезапишет другой. Дата
разводит их без координации.

## Обязательный порядок в файле

1. **Статус.** Пока не `принято`, код по этому RFC не пишется — иначе
   предложение превращается в полуреализованный факт, который потом никто не
   решается откатить.
2. **Контекст и проблема** — до предложения. Читатель должен понять, что
   не так, не читая решения.
3. **Минимум два варианта.** Один вариант означает, что обсуждения не было.
4. **Замер вместо мнения**, если выбор по числам.
5. **Решение** со ссылкой на измерение.
6. **План**, который действительно попадёт в backlog.

## Что RFC заменяет

Договорённость в `hints` или в сообщении агента. Если изменение держится на
«я и он так решили в чате» — оно не держится: агент уйдёт, и через неделю
никто не вспомнит, почему так.

Наоборот: RFC, который никто не помнит и который никто не закрыл, хуже его
отсутствия — он создаёт видимость согласованности. Отклонённые RFC **не
удаляются**: их статус меняется на `отклонено` с одной строкой причины.
